--------------------------------------------------------------------------------
ШАГ 0. БЕЗ КОДА: пустая полка «Фильмы» — это доступы, а не баг (проверено)
--------------------------------------------------------------------------------
Симптом: сериалы видны, фильмов ноль.
Причина: сервер отдаёт каждому пользователю только разрешённое
(user_library_access / user_media_access). Если на ТВ вбит ограниченный
пользователь (например, ему выданы только серии поITEMно) — /media/movies
вернёт пусто, и ТВ честно покажет «Медиатека пуста».
Лечение без кода: веб-клиент → админ → Пользователи → нужный юзер → выдать
доступ к библиотекам фильмов («Фильмы», «Фильмы 2», «Мультфильмы», ...).
Проверка: GET /api/media/movies с токеном этого юзера должен вернуть movies[].

Важно для кода ниже: сервер в /media/movies кладёт type IN ('MOVIE','VIDEO')
так задумано. А постеров у VIDEO в базе НЕТ вообще (сканер их не делает).
Отсюда два ТВ-фикса: разделить полки и подтянуть обложки через thumbnail.

Контракт серверного эндпоинта обложек (уже есть на сервере, код не нужен):
  GET /api/media/item/{mediaId}/thumbnail  →  image/jpeg (200)
  Первый вызов генерирует кадр ffmpeg'ом (~до 8с) и кеширует, дальше мгновенно.
  Без авторизации (img-тег не умеет Bearer), 404 если файла нет.

ПРОВЕРКА
--------------------------------------------------------------------------------
1. npx tsc (должно быть чисто, без ошибок).
2. npm run build, затем открыть раздел «Фильмы»: только фильмы со счётчиком.
3. Главная: полка «Видео и клипы» с обложками-кадрами (первая загрузка
   медленная — сервер режет кадры на лету; повторный заход мгновенный).
4. Если полка фильмов пуста — см. ШАГ 0 (доступы пользователя на сервере).
